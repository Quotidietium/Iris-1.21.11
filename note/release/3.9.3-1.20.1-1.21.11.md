# Iris 3.9.3-1.20.1-1.21.11 性能优化版

**日期**：2026-08-22(1-8 轮)· 2026-08-23(9-14 轮)· 2026-08-24(15-19 轮)· 2026-08-25(20-24 轮) · **分支**：`perf/optimization`（自 `901c7d659`）
**红线承诺**：全部改动经 49 个基准场景（二十四轮）的固定种子摘要（golden）逐位比对 + 3D 适配器 60 万采样 A/B 对照 + 缓存/地形循环实现 A/B 全场景对照，**地形生成与用户交互行为零变化**。

## 二十四轮优化总览

### 第 1 轮 · CPU 热点（`ca6f701e3`）
- CNG 噪声内核定参重载（`noise/fit/fitDouble`），消除每采样 varargs 数组；移除无读者的静态计数器递增
- `IrisInterpolation.getNoise`：每调用 HashMap+装箱 → 线程内原始类型备忘表（嵌套安全）
- `IrisComplex.interpolateGenerators`：hi/lo 双遍采样合并为单遍（高度流采样量减半）
- `IrisComplex.implode`：子群系稀有度映射表按群系缓存——**选择 2585→227 ns（11.4×），0 分配**
- `IRare` 稀有度挑选预计算权重表（同除法顺序，位级一致）

### 第 2 轮 · 内存/分配（`e52705c42`）
- `ChunkCache2D` 惰性 Entry（原每流每区块预分配 256 个 Entry ≈ 6KB）
- `WorldCache2D` 区块键 Long 装箱单槽备忘（volatile 原子发布）
- 2D/3D 插值捕获 lambda → 可复用适配器（3D 路径 **0 B/op**，`bench.Verify3D` 60 万采样 A/B 零差异）
- `interpolateGenerators` 原始类型对缓存
- **单线程场景分配合计 -75.2%**；主要噪声路径全部 0 B/op

### 第 3 轮 · 并发/共享缓存（`94809ea86`）
- `MultiBurst` 空闲时间戳从 AtomicLong RMW 降为 volatile 写（每 Stage 数百次 burst 不再争用缓存行）
- `BurstExecutor`/`sync` 去掉每批次列表拷贝
- `AtomicCache` 快路径单次 volatile 读
- `implode` 的 `setInferredType` 条件写（消除多线程同值写风暴）
- `WorldCache2D` CLHM → Caffeine：生产 raster 模式 8 线程 **1.54×**，聚合扩展 2.3×→3.6×
- 新增并行基准：par-cng **~7× 扩展**（证明 CNG 已无共享可变状态）

### 第 4 轮 · 数据结构/装箱消除（`5ba49090a`）
- `WorldCache2D`：Caffeine → **32 条带原始 long 键开地址表**（不可变 Node 槽，读路径无锁无记账）——命中路径 **2.8×**（18.8→6.7 ns/get），8 线程生产 raster 模式 **62.8×**（Caffeine read-buffer 争用致负扩展 → 5.9× 聚合近线性）
- `ChunkCache2D`：每格 Entry 对象 → 扁平值槽（CAS 哨兵 + 自旋，同「每格一次计算」语义）
- `IntFunction2` 原生 resolver：坐标零装箱（原每次未命中 32 B + 拆箱）
- 全 miss 场景分配再 **-53%**（2320→1079 B/op，剩余即数据结构本体）
- 验证：Caffeine 构建与 striped 构建 A/B 对照，21/21 场景 digest 位级一致

### 第 5 轮 · 地形执行器（`1c847fc8a`）
- `TerrainColumn.fill`：terrainSliver 列填充循环提取 + 列不变量提升（rock/fluid/height/data/complex）
- `IrisBiome/IrisRegion/IrisDimension.hasOres(surface)` 预检：无对应矿石时跳过每方块三级检查（典型配置 surface 轮 3 调用 + deep 轮 2 调用全部可跳）——**地形列 1.55×**（1038→671 ns，digest 位级一致）
- `IrisBiome.BARRIER` 懒加载；删除零引用死常量 `IrisDimension.STONE/WATER`
- 红线否决项记录：雕刻修改器 KMap→数组会改变装饰器 rng 顺序，不做

### 第 6 轮 · 派发扁平化（`5cbf5d569`，结论轮）
- `getNoise` 25 连 equals → enum switch；`CompiledStarcast` 128 连 if → tableswitch（分派逐点等价）
- 量化结果 **<1%**（JIT 已摊薄线性链成本）；23/23 digest 一致
- **结论：离线可验证面已收敛到本质开销**（噪声内核/数据结构本体/确定性 RNG）；后续需服务器环境实测（Mantle、装饰器、沉积）

### 第 7 轮 · Matter/Mantle 存储层 + HyperLock（`539c8275d` + `b02aaa833`）
- 推翻第 6 轮"需服务器才能测"的判断：`org.bukkit.Bukkit` 代理桩（createBlockData → JDK 动态代理）+ 桩 Iris 的 classpath 扫描 initialize，解锁整条 Matter/Mantle 存储层离线测量
- `HyperLock`：有界 LRU 锁缓存（每次加解锁装箱 Long + CLHM LRU 维护）→ **斐波那契散列条带锁池**——加解锁 **26.8×**（422→15.8 ns），0 分配；消除"驱逐仍持锁"隐患；按 key 互斥经 800 万次/键×5 轮增量单测零丢失
- `DataContainer.set`：读锁+写锁两段式（含两个潜在竞态窗口）→ 单写锁——容器写 **2.62×**（80.9→30.9 ns），108→16 B/op
- `DataContainer.trim`：红黑树映射 → int 直方图 O(n) 零分配（升序重映射次序一致，产出位级相同）
- 调色板选择阈值 4→2 比特 + `HashPalette` id→值方向装箱 KMap → 索引数组：>4 条目切片写路径免线性 equals 扫描；**id 分配序/位宽/序列化字节格式均不变（新旧存档互读）**
- `MantleWriter.acquireChunk`：不可变 ChunkMemo 原子交换备忘（方块写入聚集于同区块）——生产写链 **1.67×**（101.6→60.9 ns），132→40 B/op
- `MatterSlice.read` mapped 分支：每节点 `int[3]` 分配 → 内联取模
- 16³ Matter 序列化往返 **1.26×**，分配 **-64%**（418→152 KB/op）
- 场景 23 → **29**（DataContainer set/get、MantleChunk 写链、Matter 往返、HyperLock 命中/争用）；29/29 digest 位级一致 + contended 与纯 RNG 计数解析推导逐位相等

## 兼容性说明

- `iris.cache.dynamic` 系统属性移除（恒为惰性 Entry，原默认路径即此语义）；`iris.cache.fast` 保留
- `WorldCache2D.getSize()` 为估计值（仅指标展示）；驱逐策略从 LRU 变为条带清空（记忆化层，值不受影响）
- `WorldCache2D` resolver 参数类型改为 `IntFunction2<T>`（core 内部 API，唯一调用方 CachedStream2D 已适配）
- `HyperLock` 实现从有界 LRU 锁缓存改为定长条带锁池（构造参数语义从"最大键数"变为"条带数下限"，按 key 互斥与 API 不变；不同键碰撞时额外互斥属过度串行化，不影响正确性）
- Matter 磁盘格式零变化（调色板实现/位宽/条目序均保持，新旧存档互读）
- `IrisDimension.STONE/WATER` 公共常量移除（全仓零引用的死代码）；`IrisBiome.BARRIER` 改懒加载（值不变）
- 装饰器 partOf 分区按 biome 缓存:非法(partOf 为 null)装饰器照旧跳过,错误日志从每列一条变为每 biome 一条(生成结果不变);运行期原地修改 biome decorators 列表不再生效(加载后本就无修改点,studio 热重载走新实例不受影响)
- 引擎 4 个 Kotlin 类（ChunkContext/ChunkedDataCache/FlaggedChunk/MatterGenerator）重写为 Java:行为契约不变(构造器/Getter 签名兼容,磁盘标志格式不变,金样本位级一致);协程从生成热路径移除(kotlinx-coroutines 仍用于 MultiBurst dispatcher/PregenCache 等非每区块路径);FlaggedChunk 的 raiseFlagSuspend(挂起函数) 更名为 raiseFlag(Runnable)——唯一调用方 MatterGenerator 已同步;块内跨标志并发从"不同 Mutex 可并行"变为"单锁串行"(唯一受影响调用方本轮已改为块内顺序执行,产出确定性反而增强)
- R17：`ChunkContext` 预填充任务默认每任务 4 行（24 任务/区块，原 96）；网格值与分组无关（digest 证明），`-Diris.ctx.rows-per-task` 可覆写回 1；benchmark 新增 ctx-fill-par（饱和形状）与 ctx-orch-* 编排 A/B 场景，golden 43→48
